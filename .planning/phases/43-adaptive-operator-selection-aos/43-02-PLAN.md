**Key integration design (per D-08, D-09, D-10, D-11, D-12, D-13):**

1. **When AOS is configured**: before calling parent_crossover, the GA loop creates `AosState` instances and shares them (along with portfolio Vecs) with the offspring generation logic. The `parent_crossover` function signature gains optional AOS parameters.

2. **Per-couple dispatch** (D-08): For each parent pair, AOS selects which crossover operator to use (from portfolio), then after crossover, for each child selects which mutation operator to use.

3. **Reward accumulation** (D-11): After crossover + mutation for a couple, compute reward = compute_normalized_reward(parent_fitness, offspring_fitness, best_fitness). Write (op_idx, reward) to a Mutex accumulator.

4. **Batch update**: After the parallel loop completes, drain the Mutex accumulator and call `aos_state.record_rewards(&accumulated)`, then `aos_state.update()`.

5. **Exploration** (D-12): AosState itself handles exploration (gen < W/2 → uniform random).

6. **Coexistence with Adaptive GA** (D-13): Adaptive GA rate check still gates whether crossover/mutation happens. AOS only selects WHICH operator when the rate check passes.

7. **Portfolio-overrides-single** (D-10): When `configuration.crossover_portfolio` is `Some`, use AOS dispatch instead of `configuration.crossover_configuration.method`. The `with_crossover_method()` value is ignored.

**Design for the AOS-aware offspring loop:**

The `parent_crossover` function needs to know:
1. Which crossover operator to use for this couple (from AOS or single config)
2. Which mutation operator to use for each child (from AOS or single config)

The simplest design: **pass AOS state as `Arc<Mutex<AosState>>` into the function**, and the `process_pair` closure captures `Arc` clones. Each thread locks the mutex, calls `select_operator`, unlocks, then produces offspring. After the par loop, the outer code drains the reward accumulator.

use genetic_algorithms::operations::{Crossover, Mutation, Selection, Survivor};
use genetic_algorithms::traits::{ChromosomeT, ConfigurationT, CrossoverConfig, MutationConfig, SelectionConfig, StoppingConfig};

/// Helper: build a basic GA with AOS crossover portfolio (3 operators).
fn aos_ga_xover() -> Ga<RangeChromosome<i32>> {
    let n: i32 = 8;
    let alleles = vec![RangeGene::new(0, vec![(0_i32, 100_i32)], 0)];
    let alleles_clone = alleles.clone();

    Ga::new()
        .with_genes_per_chromosome(n.try_into().unwrap())
        .with_population_size(30)
        .with_initialization_fn(move |genes_per_chromosome, _, _| {
            range_random_initialization(genes_per_chromosome, Some(&alleles_clone), Some(false))
        })
        .with_fitness_fn(|dna: &[RangeGene<i32>]| dna.iter().map(|g| *g.value() as f64).sum())
        .with_selection_method(Selection::Tournament)
        .with_crossover_portfolio(vec![
            Crossover::Uniform,
            Crossover::SinglePoint,
            Crossover::Cycle,
        ])
        .with_mutation_method(Mutation::Swap)
        .with_aos_strategy(AosStrategy::pm_default())
        .with_problem_solving(ProblemSolving::Minimization)
        .with_survivor_method(Survivor::Fitness)
        .with_max_generations(10)
        .with_alleles(alleles)
}
