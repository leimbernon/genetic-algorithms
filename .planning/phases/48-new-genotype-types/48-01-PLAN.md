<objective>
Establish the Phase 48 foundation: a new `OperatorCompat` trait (D-04, D-05) with NO blanket implementation, two new `Crossover` enum variants (`MultiGroupPmx`, `MultiGroupOx`) referenced by GEN-04, visibility changes on `pmx_build_child` / `ox_build_child` (RESEARCH Pitfall 4), a validator function plugged into the existing validator chain, per-type empty `OperatorCompat` impls for `BinaryChromosome` / `RangeChromosome<T>` / `ListChromosome<T>`, and Wave 0 test scaffolds for every later-wave addition.

Purpose: Implements the trait-level half of GEN-01 (build-time operator rejection) and the enum-level prerequisites for GEN-04 (multi-group crossover variants must exist before chromosomes can claim them in `valid_crossovers()`). Establishes the validator chain hook so later plans only have to add an `impl OperatorCompat` per chromosome type with the restricted sets.

**Design correction vs RESEARCH §Pattern 4:** RESEARCH originally proposed a blanket `impl<T: LinearChromosome> OperatorCompat for T {}`. That conflicts with the concrete restriction impls required for `UniqueChromosome<T>` and `MultiUniqueChromosome<T>` later (Rust stable does not allow specialization). The corrected approach is: NO blanket impl; instead, add per-type empty impls for the three existing chromosome types (default-`None` methods are inherited from the trait, so the impl bodies are empty `{}`). This preserves backward compatibility for users of existing types while permitting concrete restriction impls for new permutation types in 48-02 and 48-04.

Output: New `src/traits/operator_compat.rs`, two new variants in `src/operations.rs` `Crossover` enum, `pub(crate)` visibility on `pmx_build_child` and `ox_build_child`, new validator function in `src/validators/generic_validator.rs`, `operator_compat_check` wired into `Ga::build()`, empty `OperatorCompat` impls on three existing chromosomes, Wave 0 test files and modules, updated `src/traits.rs` and `src/lib.rs` re-exports.
</objective>
