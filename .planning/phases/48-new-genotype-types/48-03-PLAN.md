<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User fitness fn closure → MultiRangeChromosome::calculate_fitness | Arbitrary user code invoked per chromosome |
| User bounds + mutation_rates slices → multi_range_random_initialization | Length mismatch could underspecify mutation_rates |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-07 | Tampering | multi_range_random_initialization with shorter mutation_rates slice | accept | Function uses `mutation_rates.get(i).copied().unwrap_or(0.1)` — short slices fall back to a default rate; existing `Ga::build()` validators detect zero-length dna |
| T-48-08 | Denial of Service | Per-gene Gaussian mutation on huge dna | accept | Mutation samples one random gene per call (`rng.random_range(0..len)`) — O(1) per mutation event regardless of dna length |
| T-48-09 | Tampering | User-supplied bounds where lo >= hi | mitigate | `rng.random_range(lo..hi)` panics if `lo >= hi`; downstream `Ga::build()` validator chain should catch this — add a validator check in the multi_range_random_initialization function header doc that lo < hi is required (initial design choice — explicit panic on misuse rather than silent corruption) |
| T-48-SC | Tampering | npm/pip/cargo installs | accept | No new dependencies |
</threat_model>
