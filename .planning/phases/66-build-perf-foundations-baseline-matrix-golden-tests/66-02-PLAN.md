  <action>
Create `.github/workflows/feature-matrix.yml` with the following structure:

Trigger (per D-01): `on: push: branches: [main, "milestone/**"]`. No `pull_request` trigger. The workflow MUST NOT run on PRs.

Name: `Feature matrix`

Single job named `test-matrix` using `runs-on: ubuntu-latest`.

Use `strategy: matrix: include:` (not `matrix: feature:`) to allow the wasm32 entry to use a different `run` command than the others. The matrix entries are:

1. `{ name: "default",          features: "",                        cmd: "cargo test --quiet" }`
2. `{ name: "serde",            features: "--features serde",        cmd: "cargo test --quiet --features serde" }`
3. `{ name: "visualization",    features: "--features visualization", cmd: "cargo test --quiet --features visualization" }`
4. `{ name: "benchmarks",       features: "--features benchmarks",   cmd: "cargo test --quiet --features benchmarks" }`
5. `{ name: "observer-tracing", features: "--features observer-tracing", cmd: "cargo test --quiet --features observer-tracing" }`
6. `{ name: "observer-metrics", features: "--features observer-metrics", cmd: "cargo test --quiet --features observer-metrics" }`
7. `{ name: "all-features",     features: "--all-features",          cmd: "cargo test --quiet --all-features" }`
8. `{ name: "wasm32",           features: "",                        cmd: "cargo check --target wasm32-unknown-unknown --lib" }`

Job steps:
1. `actions/checkout@v4`
2. `dtolnay/rust-toolchain@stable` with `targets: wasm32-unknown-unknown` (needed for entry #8; harmless for others)
3. `Swatinem/rust-cache@v2` with `key: feature-matrix-${{ matrix.name }}`
4. A single `run` step: `${{ matrix.cmd }}` with `name: ${{ matrix.name }}`

The wasm32 entry's `cmd` uses `cargo check --target wasm32-unknown-unknown --lib`. The `.cargo/config.toml` already sets `--cfg getrandom_backend="wasm_js"` for the wasm32 target, so no additional `RUSTFLAGS` env var is needed in the workflow — the target-specific rustflags in config.toml are applied automatically by cargo when `--target wasm32-unknown-unknown` is given.

Add `permissions: contents: read` at the job level (consistent with existing workflows).

Add `env: CARGO_TERM_COLOR: always` at the workflow level.

Do NOT add `fail-fast: false` — default fail-fast behavior is acceptable. Do NOT add `continue-on-error`.
