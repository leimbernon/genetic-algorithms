  </read_first>
  <action>
    Step 1 — Build the inventory:
    Run `grep -rn '^pub fn\|^pub struct\|^pub trait\|^pub enum' src/ --include='*.rs'` and filter out:
    - Lines containing `pub(crate)` (excluded per D-11)
    - Items inside `impl` blocks (these are trait impl items per D-11 exclusion — only MODULE-ROOT `pub fn` count)
    - Type aliases (`pub type ...`) — excluded per D-11
    - Enum variants — excluded per D-11 (only the `pub enum` itself counts, not its variants)

    Cross-reference each remaining hit against `src/lib.rs` to confirm it is actually re-exported (user-facing). Items NOT re-exported are still "user-facing" if their containing module is `pub mod` and reachable through a re-exported parent.

    Build the inventory list and save it to `.planning/phases/64-test-doc-quality/64-DOC-INVENTORY.md` with columns: `file:line | item | classification (complex|simple) | needs_examples (yes|already_has)`.

    Step 2 — Classify each item:
    - **Complex** (use `no_run` per D-12): items requiring engine setup — anything in `src/engines/`, `src/configuration.rs`, builder methods on configuration structs, operator enums (`Selection`, `Crossover`, `Mutation`, `Survivor`, `Extension`), `ConfigurationT` trait methods, `GaObserver` trait, etc.
    - **Simple** (use runnable `rust` per D-13): gene types (`Binary`, `Range<T>`), small utility structs/enums (`GaError` variants — actually variants are excluded, but the `GaError` enum itself if root-public is simple), `Population` constructors with trivial inputs, anything self-contained.

    Step 3 — Add `# Examples` blocks:
    For each item marked `needs_examples: yes`, add a `# Examples` section to its rustdoc:
    - Place it AFTER the existing `# Errors`/`# Panics`/argument descriptions
    - Use complete `use` statements via the crate's re-export paths (`use genetic_algorithms::engines::ga::Ga;`), per Pitfall 5
    - For complex items: ` ```rust,no_run ` — show realistic usage that compiles but doesn't need to execute
    - For simple items: ` ```rust ` — show short runnable code (≤ 10 lines), include at least one `assert!` to make the example self-validating

    For items that ALREADY have a `# Examples` block (left over from phase 46), VERIFY the example still compiles under `cargo test --doc --all-features`. Update if it does not.

    Step 4 — Run `cargo test --doc --all-features` repeatedly during the task; fix any compilation errors in doc examples immediately. The most common failures (per Pitfall 5) are missing `use` statements and incorrect public paths.

    Step 5 — Run `cargo doc --no-deps --all-features 2>&1 | grep -i warning` and fix any rustdoc warnings (broken intra-doc links, missing `# Safety` sections on unsafe fn, etc.). The target is ZERO warnings.

    Implementation strategy for scale (~100-150 items): work by module subtree. Start with `src/types/` (smallest, simplest), then `src/operations/`, then `src/engines/` (largest, most complex — use `no_run` heavily). Commit per-subtree to keep git history reviewable.
  </action>
