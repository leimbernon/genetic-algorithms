<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → GpChromosome::dna() | Calling linear operator on a tree chromosome causes explicit panic (not silent data corruption) |
| user-supplied GpNode::evaluate() | User code executes inside fitness evaluation loop — panics propagate to engine level |
| user-supplied max_depth / max_node_count | Config values must be validated at build() time to prevent memory exhaustion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | Tampering | GpChromosome::dna() stub | mitigate | panic! with explicit message prevents silent data corruption when linear operators are mistakenly applied to tree chromosomes |
| T-53-02 | Denial of Service | GpConfiguration::max_depth = usize::MAX | mitigate | GpConfiguration::build() validates max_depth > 0 and max_depth <= 1000 (documented hard cap); returns GaError::ConfigurationError |
| T-53-03 | Denial of Service | GpConfiguration::max_node_count unchecked | mitigate | build() validates max_node_count >= max_depth and max_node_count <= 100_000 |
| T-53-SC | Tampering | serde_stacker (Wave 3 install) | accept | serde_stacker is a dtolnay crate (author of serde/syn/quote); [ASSUMED] from crates.io; human verify checkpoint added in Wave 3 plan before Cargo.toml commit |
