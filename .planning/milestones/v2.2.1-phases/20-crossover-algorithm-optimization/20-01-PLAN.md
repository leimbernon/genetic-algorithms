Rewrite the `pmx_build_child` function body. Keep the function signature identical: `fn pmx_build_child<G: GeneT>(donor: &[G], other: &[G], start: usize, end: usize) -> Vec<G>`.

Changes to make:

1. Build the position map ONCE before the chain loop:
   ```rust
   let pos_in_other: HashMap<i32, usize> = other.iter().enumerate().map(|(i, g)| (g.id(), i)).collect();
   ```

2. Replace `Vec<Option<G>>` child construction with direct `Vec<G>`:
   ```rust
   let mut child = other.to_vec();
   ```

3. Copy the donor segment into the child (overwrite pre-filled values):
   ```rust
   for i in start..=end {
       child[i] = donor[i].clone();
   }
   ```

4. Keep the existing `segment_ids: HashMap<i32, usize>` build (line 80) — this maps donor segment gene IDs.

5. Replace the chain-following loop (lines 85-111). For each position `i` in `start..=end`:
   - Let `gene = &other[i]`
   - If `segment_ids.contains_key(&gene.id())`, skip (gene already placed in child segment)
   - Otherwise, follow the mapping chain:
     - `let mut mapped_id = donor[i].id();`
     - Loop: look up `mapped_id` in `pos_in_other` (HashMap O(1) lookup, not linear scan). Get the position. If the position is outside `[start, end]`, set `child[pos] = gene.clone()` and break. If inside the segment, set `mapped_id = donor[pos].id()` and continue the chain.
   - Use `pos_in_other[&mapped_id]` or `pos_in_other.get(&mapped_id).expect(...)` for the lookup.

6. Remove Step 3 (the fill-remaining loop at lines 113-118) — the pre-fill from `other.to_vec()` handles this automatically.

7. Remove the `.into_iter().map(unwrap)` epilogue (lines 120-133) — the child is already `Vec<G>`, not `Vec<Option<G>>`.

8. Return `child` directly.

Do NOT change the `pmx()` function — only `pmx_build_child` internals change. The `use std::collections::HashMap;` import is already present.
