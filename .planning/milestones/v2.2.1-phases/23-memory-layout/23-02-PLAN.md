**Replace the dedup block** (the `let mut seen: HashSet<Vec<i32>> = ...` and `chromosomes.retain(...)` section) with:

```rust
let mut seen: HashMap<u64, Vec<i32>> = HashMap::new();
chromosomes.retain(|c| {
    // Incremental hash of gene IDs — no Vec<i32> allocation on common path
    let mut hasher = DefaultHasher::new();
    for g in c.dna() {
        g.id().hash(&mut hasher);
    }
    let h = hasher.finish();

    match seen.entry(h) {
        std::collections::hash_map::Entry::Vacant(e) => {
            // First chromosome with this hash — store gene IDs for collision check
            let ids: Vec<i32> = c.dna().iter().map(|g| g.id()).collect();
            e.insert(ids);
            true // keep
        }
        std::collections::hash_map::Entry::Occupied(e) => {
            // Hash collision — exact compare gene IDs
            let ids: Vec<i32> = c.dna().iter().map(|g| g.id()).collect();
            if ids != *e.get() {
                true // hash collision but distinct chromosome — keep
            } else {
                false // true duplicate — remove (best was kept via prior sort)
            }
        }
    }
});
```

**Keep the sort and logging unchanged** — the sort by fitness (best first) ensures the first-seen chromosome per gene-ID pattern is the best one, matching the existing semantics exactly.

Hash content is gene IDs only (via `g.id()`) — consistent with current `Vec<i32>` key semantics. Adding gene values would require `GeneT: Hash` which is a breaking change (deferred).
