### 🚧 v2.2.1 — Performance Optimizations (In Progress)

**Milestone goal:** Eliminate unnecessary clones, redundant allocations, and suboptimal algorithms across the GA engine — all internal, no public API changes. Issues: #187–#192.

- [x] **Phase 19: Clone Elimination** — Defer parent clones until needed; build crossover children directly; use in-place mutation for numeric and index operators (completed 2026-03-30)
- [x] **Phase 20: Crossover Algorithm Optimization** — Replace O(n²) linear scans in Order Crossover and PMX with O(n) position maps (completed 2026-03-30)
- [x] **Phase 21: Selection Algorithm Optimization + Allocation Reduction** — Binary search for Rank and Boltzmann selection; collect fitness values once per generation (completed 2026-03-31)
- [x] **Phase 22: Survivor & Extension Optimization** — O(n) elite reinsertion and mass genesis best-scan; relaxed RNG atomic ordering; parallel extension regrow (completed 2026-03-31)
- [x] **Phase 23: Memory Layout** — Shared Arc range slice for Range genes; Copy-type value returns; unused field removal; inline annotation; incremental deduplication hash (completed 2026-04-04)
- [x] **Phase 24: Minor Improvements** — Move stats instead of clone; O(n) truncation and best-scan deduplication; O(n) island migration sort elimination (completed 2026-04-05)

## Phase Details

### Phase 13: GaObserver Base Trait
**Goal**: Users can attach a structured observer to `Ga<U>` and receive lifecycle notifications with zero overhead when no observer is attached
**Depends on**: Nothing (first phase of this milestone)
**Requirements**: OBS-01, OBS-02, OBS-03, OBS-04
**Success Criteria** (what must be TRUE):
  1. User can call `ga.with_observer(arc_observer)` and have `on_run_start`, `on_generation_end`, `on_new_best`, `on_run_end`, `on_stagnation`, and `on_extension_triggered` fire at the correct points in the GA loop
  2. A custom observer that implements only one hook compiles without error — all other hooks have default no-op bodies
  3. Running `Ga<U>` with no observer attached produces identical output and timing to pre-v2.2.0 (zero-overhead branch confirmed by benchmarks)
  4. A custom observer type that is not `Send + Sync` is rejected at compile time when passed to `with_observer()`
**Plans:** 2/2 plans complete

Plans:
- [x] 13-01-PLAN.md — GaObserver trait definition, ExtensionEvent, NoopObserver, Extension::as_str(), Reporter deprecation
- [x] 13-02-PLAN.md — Ga<U> integration (observer field, builder, notify helper, 12 call sites) + integration tests

### Phase 20: Crossover Algorithm Optimization
**Goal**: PMX Crossover replaces its O(n^2) inner-loop position scan with an O(n) hash-based position map; OX is already O(n) from a prior commit
**Depends on**: Phase 19
**Requirements**: ALGO-01, ALGO-02
**Success Criteria** (what must be TRUE):
  1. `cargo test` passes — existing OX and PMX correctness tests continue to pass with identical output for seeded inputs
  2. OX implementation contains a position-map construction step (e.g., `HashMap` or index array) rather than a linear `.position()` search inside the fill loop
  3. PMX implementation contains a position-map construction step rather than a linear `.position()` search inside the mapping loop
  4. No public API change — `CrossoverOperator::crossover()` signature unchanged
**Plans:** 1/1 plans complete

Plans:
- [ ] 20-01-PLAN.md — PMX HashMap position map + direct Vec child construction; mark ALGO-01 complete

### Phase 21: Selection Algorithm Optimization + Allocation Reduction
**Goal**: Rank Selection and Boltzmann Selection use binary search instead of O(M×N) linear scans; fitness values are collected once per generation and shared across extension, niching, and stats — eliminating two redundant O(n) allocations
**Depends on**: Phase 18
**Requirements**: ALGO-03, ALGO-04, ALLOC-01, ALLOC-02
**Success Criteria** (what must be TRUE):
  1. `cargo test` passes — Rank and Boltzmann selection produce correct parent pairs under all population sizes and configurations
  2. Rank Selection uses `partition_point()` binary search — verified by inspection of `src/operations/selection/rank.rs`
  3. Boltzmann Selection performs a single-pass cumulative probability construction followed by binary search — no O(M×N) loop remains
  4. Fitness values are computed once in the generation loop and passed into extension, niching, and stats; the two redundant `.iter().map(|c| c.fitness())` collection calls are removed from `src/ga.rs`
  5. Niching distance matrix is computed on-the-fly (element by element) instead of allocating an O(n²) matrix upfront
**Plans:** 3/3 plans complete

Plans:
- [ ] 21-01-PLAN.md — Rank + Boltzmann selection: partition_point binary search (ALGO-03, ALGO-04)
- [ ] 21-02-PLAN.md — apply_fitness_sharing_with_dna on-the-fly function + tests (ALLOC-02)
- [ ] 21-03-PLAN.md — Merge fitness collection in ga.rs + wire on-the-fly niching (ALLOC-01, ALLOC-02)

### Phase 22: Survivor & Extension Optimization
**Goal**: Elite reinsertion and mass genesis use O(n) selection instead of full sorts; RNG atomic ordering is relaxed to the minimum correct ordering; extension population regrow runs in parallel
**Depends on**: Phase 18
**Requirements**: ALGO-05, ALGO-06, CONC-01, CONC-02
**Success Criteria** (what must be TRUE):
  1. `cargo test` passes — elitism behavior is unchanged for all survivor strategies; extension tests pass
  2. Elite reinsertion calls `select_nth_unstable_by()` instead of a full sort — verified by inspection of the elitism code path in `src/ga.rs`
  3. Mass genesis best-chromosome scan uses two linear passes (one for best, one for second-best) — no `.sort()` or `.sort_unstable()` call in `MassGenesis` apply path
  4. RNG seed fetch uses `Acquire` ordering and counter increment uses `Relaxed` ordering — verified by inspection of `src/rng.rs`
  5. Extension population regrow uses `rayon::par_iter` — verified by inspection of the extension apply path
**Plans:** 2/2 plans complete

Plans:
- [ ] 22-01-PLAN.md — O(n) elite reinsertion (select_nth_unstable_by) + O(n) mass genesis single-pass top-2 scan
- [ ] 22-02-PLAN.md — Relaxed RNG atomic orderings (Acquire/Release/Relaxed) + parallel extension regrow (rayon)

### Phase 23: Memory Layout
**Goal**: Range genes share a single Arc-allocated range slice per chromosome instead of per-gene heap allocations; Copy-type accessors avoid unnecessary `.clone()`; dead fields and inlinable hot functions are cleaned up; mass deduplication avoids per-chromosome Vec allocation
**Depends on**: Phase 18
**Requirements**: MEM-01, MEM-02, MEM-03, MEM-04, MEM-05
**Success Criteria** (what must be TRUE):
  1. `cargo test` and `cargo test --features serde` pass with zero failures
  2. `Range` gene struct holds `Arc<[(T, T)]>` for its range bounds — verified by inspection of `src/genotypes/range.rs`
  3. `Range::value()` for `Copy` types returns the value directly without a `.clone()` call
  4. `Population` struct no longer contains a `generation_numbers` field — `cargo build` succeeds with no dead_code warnings for that field
  5. `MassDeduplication` uses an incremental `DefaultHasher` instead of allocating a `Vec<i32>` per chromosome during deduplication
**Plans:** 2/2 plans complete

Plans:
- [ ] 23-01-PLAN.md — Arc range slice for Range genes, Copy-specialized value(), #[inline] FitnessFnWrapper::call()
- [ ] 23-02-PLAN.md — Remove generation_numbers from Population, DefaultHasher mass deduplication

### Phase 24: Minor Improvements
**Goal**: Stats, truncation selection, best-chromosome scan, and island migration each shed one unnecessary allocation or sort, completing the full set of v2.2.1 optimizations
**Depends on**: Phase 18
**Requirements**: MISC-01, MISC-02, MISC-03, MISC-04, MISC-05
**Success Criteria** (what must be TRUE):
  1. `cargo test` passes — all island migration, stats, and selection tests produce correct results
  2. `GenerationStats` is moved (not cloned) when appended to the stats history vec — no `.clone()` call on `GenerationStats` in the push path
  3. Truncation Selection calls `select_nth_unstable()` for O(n) partitioning — no `.sort()` or `.sort_unstable()` call in its survivor path
  4. Best chromosome scan in `fitness_calculation()` is used directly — no second pass over the population to find the best after fitness evaluation
  5. Island migration uses `select_nth_unstable()` for migrant selection and replacement, and shares migrant data without cloning per-neighbor vectors
**Plans:** 2/2 plans complete

- [ ] 24-01-PLAN.md — Push-last stats move, O(n) truncation partitioning, best-scan deduplication
- [ ] 24-02-PLAN.md — O(n) island migration sort elimination, Arc migrant sharing
