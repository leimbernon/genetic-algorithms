<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> mozilla-actions/sccache-action | Action is maintained by Mozilla; pinned to exact tag `v0.0.9`. Confirmed via GitHub API (published 2025-06-18). |
| CI runner -> sccache binary -> GHA cache backend | sccache reads/writes compiler artifact cache via the GitHub Actions cache API. The cache is scoped per-repository and signed by GHA infrastructure. |
| Cached compiler output -> subsequent CI runs | sccache caches rustc output keyed on inputs (compiler version, source hash, flags). A poisoned cache would surface as a build failure or test failure — same blast radius as a bad Cargo.lock. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-04-T | Tampering | mozilla-actions/sccache-action | mitigate | Pinned to exact tag `v0.0.9` (never `@latest` or `@main`); D-05 forbids version drift; acceptance criteria assert exact version string |
| T-67-04-T2 | Tampering | sccache cache poisoning | accept | Cache is scoped to repo + branch; poisoned entry would cause loud test failure on next CI run; standard GHA cache trust model |
| T-67-04-D | Denial of service | CI workflows | mitigate | sccache failure does not block build (sccache falls through to direct rustc invocation); `--show-stats` step is the only step that requires the binary, runs at end of job |
| T-67-04-I | Information disclosure | cache contents | accept | Cached compiler output contains no secrets; standard build artifacts |
| T-67-04-SC | Tampering | GitHub Actions supply chain | mitigate | Exact tag pin (v0.0.9), Mozilla-maintained, verified via GitHub API in RESEARCH.md; no crate dep added (dep_count invariant preserved) |
</threat_model>
