<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> taiki-e/install-action | Action downloads pre-built nextest binary from nextest-rs GitHub releases. Pinned to `@nextest` (alias for latest stable release). Supply-chain risk is low because nextest is a widely-used Rust ecosystem tool with reproducible releases. |
| CI runner -> nextest | nextest runs the same test code as `cargo test`; no new attack surface — it only changes the runner, not the tests. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-02-T | Tampering | taiki-e/install-action | accept | Action is widely used (Tokio contributor); `@nextest` tag tracks official nextest releases; alternative `cargo install cargo-nextest --locked` is documented as fallback in RESEARCH.md |
| T-67-02-SC | Tampering | GitHub Actions supply chain | accept | No crate dep added; only an Actions step. dep_count invariant preserved. |
| T-67-02-D | Denial of service | CI test runner | mitigate | Local `cargo test` retained as fallback (D-04); if nextest action breaks, contributors and CI can fall back to `cargo install cargo-nextest --locked` documented in TESTING.md |
</threat_model>
