<objective>
Replace the overloaded `mutate(step, sigma)` signature and the global `MutationConfiguration` operator params with per-variant inline params (#249). `Mutation` enum variants carry their own `Option<f64>` parameters and lose `Copy` (deriving `Clone`). `MutationOperator::mutate` takes `&Mutation` and each variant extracts its own params. `MutationConfiguration` drops all operator-specific fields. The GA loop's ~60-line if/else mutation dispatch collapses to a single trait call, with special-cases preserved for variants needing population/generation/length context.

Purpose: Each mutation operator owns its parameters explicitly, eliminating the "which config field does this operator read" coupling. v3.0.0 breaking change for custom `MutationOperator` impls and for users who set mutation params via builder methods — documented in MIGRATION.md (Phase 65).

Output: Parameterized Mutation enum, updated trait + dispatch, slimmed config + builder, collapsed GA-loop dispatch, updated mutation tests.

DEPENDS ON Plan 01 (Wave 1): both modify src/engines/ga.rs and src/traits/operators.rs; Plan 01's selection changes must land first to avoid conflicts.
</objective>

The research flagged ambiguities (A1, A2, A6, A7) requiring a planner decision. Resolutions (apply exactly):

- A1 (Differential): becomes `Mutation::Differential { f: Option<f64> }`. The `f` parameter moves out of MutationConfiguration.differential_f into the variant. Default when None: 0.5. Rationale: D-08 removes ALL operator-specific config fields; differential_f has nowhere else to live. This OVERRIDES the CONTEXT D-06 listing of Differential as a unit variant.
- A2 (NonUniform): becomes `Mutation::NonUniform { b: Option<f64> }`. The `b` parameter moves out of MutationConfiguration.non_uniform_b into the variant. Same rationale as A1.
- A3 (Insertion/Deletion): remain UNIT variants (no inline params, per D-06). They stay special-cased in the GA loop (dispatched via factory_with_chromosome_length, NOT through the bare trait call) because their length bounds come from LimitConfiguration, not from the enum.
- A6 (Gaussian default): `None` → 0.1 (per D-06; this is an intentional behavior change from the current 1.0 default — document in MIGRATION.md).
- A7 (Creep default): `None` → 0.01 (per D-06; intentional change from current 1.0 — document in MIGRATION.md).
- factory_with_params / factory_self_adaptive retention: keep them as internal callable helpers if still referenced by the special-case paths; do not add `#[deprecated]` in this phase (that is Phase 65 scope). Remove them only if they become fully unreferenced after the dispatch collapse.
</resolved_ambiguities>
