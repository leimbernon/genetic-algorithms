  <action>
Create `bench/build_perf.sh` as a bash script (shebang `#!/usr/bin/env bash`, `set -euo pipefail`). The script measures the full suite described in BUILD-PERF.md §CC-1, in this exact order:

1. `cargo clean && time cargo build --quiet` (default features) — capture wall-clock into `dev_build_s`
2. `cargo clean && time cargo check --target wasm32-unknown-unknown --lib` — capture into `wasm_check_s`
3. `cargo clean && time cargo test --quiet` — capture into `test_suite_s`
4. `cargo tree --prefix none | sort -u | wc -l | tr -d ' '` — capture into `dep_count` (integer)
5. `cargo public-api 2>/dev/null | sha256sum | awk '{print $1}'` — capture into `public_api_hash` (hex string). If `cargo public-api` is not installed, set `public_api_hash` to `"unavailable"` and print a warning (do not abort).
6. For each of the four reference examples (`rastrigin`, `nsga2_zdt1`, `cma_es_rastrigin`, `pso_rastrigin`): run `cargo run --example <name> --release -- --seed 42` and capture stdout to `target/build-perf/<name>-seed42.txt`. These files are used by Plan 66-03; the script does not assert their content.

Time capture: use `{ time <cmd>; } 2>&1 | grep real | awk '{print $2}'` and convert the `Nm NNs` format to decimal seconds. Store in a shell variable named `dev_build_s`, `wasm_check_s`, `test_suite_s` respectively.

Output directory: `mkdir -p target/build-perf/`. Write a JSON object to `target/build-perf/results.json` with exactly the six fields from D-08:
```
dev_build_s, wasm_check_s, test_suite_s, dep_count, public_api_hash, captured_at
```
`captured_at` is `$(date +%Y-%m-%d)`. Use `printf` or a heredoc to write the JSON — do not require `jq` as a system dependency.

Commit flag: accept an optional first argument `--commit`. When passed, copy `target/build-perf/results.json` to `.planning/baselines/v3.0.0-baseline.json` (per D-11). Print "Baseline committed to .planning/baselines/v3.0.0-baseline.json" to stdout.

Make the script executable: `chmod +x bench/build_perf.sh`.

Add `target/build-perf/` to `.gitignore` if not already present (check first with `grep -q 'target/build-perf' .gitignore`).

Do NOT add a `bench/` entry to `.gitignore` — the script itself must be tracked.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell script → cargo | Script invokes cargo subcommands; cargo executes crate code and network calls for deps |
| script stdout → JSON | Timing output is parsed with awk/grep; malformed output could produce invalid JSON |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-01 | Tampering | `target/build-perf/results.json` | accept | File is gitignored and ephemeral; the committed baseline in `.planning/baselines/` is the canonical record and is tracked by git |
| T-66-02 | Information Disclosure | `cargo public-api` output | accept | Public API snapshot is intentionally public; stored hash is non-reversible |
| T-66-03 | Denial of Service | `cargo clean` in script | accept | Script is a local-developer tool, not a CI gate in this plan; Wave 1 gate is Plan 66-03 |
| T-66-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan; script uses only cargo subcommands already in Cargo.toml |
</threat_model>
