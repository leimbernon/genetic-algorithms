    The OPENING sentence of Description MUST make the dual-engine distinction explicit (Pitfall 5): EdaEngine uses a Bernoulli model (binary genes, classic UMDA); EdaRealEngine uses a Gaussian univariate model (continuous genes, RealGene-bound). One shared EdaConfiguration drives both — the model is selected by the engine type (and gene type), not by a config flag. Explain UMDA: each generation, estimate a univariate probability model from the best selection-ratio fraction of the population, then sample offspring from that model — no crossover or mutation operators.

    Mention the EdaModel enum returned in EdaResult: Bernoulli(Vec<f64>) (probability per position) and Gaussian { means: Vec<f64>, stds: Vec<f64> }.

    When to Use bullets (Problem type / Variable type / Key strength / Key weakness): binary problems with deception/epistasis (trap functions) for EdaEngine, continuous for EdaRealEngine; key strength is model-building avoids crossover disruption of block structure and learns near-independent variable distributions; key weakness is UMDA is univariate so it does NOT capture inter-variable dependencies (for that, multivariate EDAs like BOA/MIMIC would be needed).

    Quick Reference parameter table "| Field | Type | Default | Description |" with the verified EdaConfiguration fields and defaults: population_size (usize, 100 — EDA needs larger pops to estimate the model), max_generations (usize, 500), problem_solving (ProblemSolving, Maximization — call out explicitly that this default DIFFERS from CMA/PSO which default to Minimization, per Pitfall 2), fitness_target (Option<f64>, None), selection_ratio (f64, 0.5 — fraction of population feeding model estimation, must be in (0.0, 1.0], minimum 1 parent enforced), fitness_cache_size (Option<usize>, None).

    Complete Example: per D-05 provide TWO contrasting `rust,ignore` fenced snippets with precise module paths (NOT glob):

Binary -> Bernoulli: EdaConfiguration::default() with .with_population_size(300), .with_selection_ratio(0.3), .with_problem_solving(ProblemSolving::Maximization), then EdaEngine::<BinaryChromosome>::new(config, init_fn, fitness_fn). Use a chromosome type alias or a placeholder init/fitness closure consistent with examples/eda_trap.rs.
      2. Continuous -> Gaussian: EdaConfiguration::default() with .with_population_size(100), .with_selection_ratio(0.5), .with_problem_solving(ProblemSolving::Minimization), then EdaRealEngine::<RangeChromosome<f64>>::new(config2, init_fn2, fitness_fn2).
    Builder method names: with_population_size, with_max_generations, with_problem_solving, with_fitness_target, with_selection_ratio, with_fitness_cache_size (EDA uses the `_size` suffix).
