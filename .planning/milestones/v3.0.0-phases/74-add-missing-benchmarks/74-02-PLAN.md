`Cargo.toml`.

    CRITICAL API CORRECTION (verified against src/engines/gp/engine.rs and configuration.rs):
    `GpGa::with_ramped_half_and_half(config, fitness_fn)` takes a `GpConfiguration` VALUE directly — it does
    NOT take the output of `.build()`. `GpConfiguration::build(&self)` returns `Result<(), GaError>` (validation
    only; the config is validated again when `run()` is called). The RESEARCH.md sketch showing
    `GpConfiguration::new()...build().unwrap()` as the constructor argument is WRONG — `build()` returns `()`,
    not a config. Construct the config with the builder and pass it directly:
    `let config = GpConfiguration::new().with_population_size(pop_size).with_max_generations(20).with_max_depth(6);`
    (max_generations=20 and max_depth=6 keep pop_500 runtime CI-friendly per Pitfall 6).

    Symbolic-regression fitness fn over `&Node<MathNode>` targeting `f(x) = x^2 + x + 1`:
    `fn symreg_fitness(tree: &Node<MathNode>) -> f64` — evaluate at 21 sample points x in -10..=10,
    `let pred = tree.eval_with_vars(&[x]);` (eval_with_vars is an inherent method on `Node<MathNode>` —
    src/engines/gp/primitives.rs:274), `let target = x * x + x + 1.0;`, accumulate `(pred - target).powi(2)`,
    return MSE = sum / 21.0 (lower is better; minimize).

    Construct the engine with an explicit turbofish to avoid type-inference failure (Open Questions 2):
    `let mut engine = GpGa::<MathNode>::with_ramped_half_and_half(config, symreg_fitness);`
    `GpGa::run()` returns `Result<GpResult<MathNode>, GaError>` — discard the whole Result with `let _ = engine.run();`.
