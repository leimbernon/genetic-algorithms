<objective>
Add divan feature-overhead benchmarks for the three GA features that currently
have no coverage, each as a two-variant on/off comparison mirroring
`benches/metrics_observer.rs`:
- AOS (D-02): `Ga` with crossover portfolio + `AosStrategy` vs plain `Ga`, Rastrigin 10D, same population.
- Surrogate (D-03): surrogate-assisted `Ga` vs plain `Ga` on a deliberately slow fitness.
- Batch fitness (D-04): `Ga` with a batch evaluator vs `Ga` with a per-call fitness fn, sphere, matched population.

Purpose: Close the feature-coverage gap for AOS, surrogate, and batch fitness
(GOAL; closes #267). Each file follows the `benches/aos.rs` / `surrogate.rs` /
`batch_fitness.rs` naming from D-01.
Output: `benches/aos.rs`, `benches/surrogate.rs`, `benches/batch_fitness.rs`,
and three new `[[bench]]` entries in `Cargo.toml`.

Note: this plan edits `Cargo.toml` (shared with plans 74-01 and 74-02), so it
runs in a later wave to avoid a same-wave file conflict.
</objective>

Shared GA-builder note for all three tasks: a buildable `Ga<RangeChromosome<f64>>`
needs `with_chromosome_length(ChromosomeLength::Fixed(N))`, `with_population_size(..)`,
`with_initialization_fn(..)` (use `range_random_initialization`), `with_selection_method`,
`with_crossover_method`, `with_mutation_method`, `with_survivor_method`,
`with_problem_solving`, `with_max_generations`, then `.build().expect(..)` and
`.run()` (returns `Result` — discard with `let _ = ga.run();`). These builder
methods come from the `ConfigurationT` trait family; import
`genetic_algorithms::traits::{ConfigurationT, CrossoverConfig, MutationConfig, SelectionConfig, StoppingConfig}`
(same import block as `benches/metrics_observer.rs` and `examples/surrogate_rastrigin.rs`).
`ChromosomeLength` is re-exported at the crate root: `genetic_algorithms::ChromosomeLength`.
