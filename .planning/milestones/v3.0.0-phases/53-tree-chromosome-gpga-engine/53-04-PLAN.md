From Cargo.toml (current):

serde_stacker pattern (from research §Serde / Deep Trees):
  #[cfg(feature = "serde")]
  impl<'de, N: GpNode + serde::Deserialize<'de>> serde::Deserialize<'de> for Node<N> {
      fn deserialize<D: serde::Deserializer<'de>>(d: D) -> Result<Self, D::Error> {
          serde_stacker::deserialize(d)
      }
  }
  #[cfg(feature = "serde")]
  impl<N: GpNode + serde::Serialize> serde::Serialize for Node<N> {
      fn serialize<S: serde::Serializer>(&self, s: S) -> Result<S::Ok, S::Error> {
          serde_stacker::serialize(self, s)
      }
  }

Note: serde_stacker::serialize/deserialize wrap the standard derived impl. Node<N> must NOT also have #[derive(Serialize, Deserialize)] if these manual impls are provided (duplicate impl). Instead, Node<N> should have #[cfg_attr(feature = "serde", derive(Serialize, Deserialize))] removed and replaced entirely with the manual impls above (which internally delegate to derive via a helper type). ACTUALLY: serde_stacker docs show that you keep the derived impls and wrap only the Deserializer at the entry point. The custom Deserialize impl for Node<N> calls serde_stacker::deserialize(d) which internally creates a stack-growing deserializer and delegates to the standard derived logic. So: remove #[cfg_attr(feature = "serde", derive(Serialize, Deserialize))] from Node<N> and add the manual impls that use serde_stacker. GpChromosome<N> can keep #[cfg_attr(feature = "serde", derive(Serialize, Deserialize))] since its root field is Box<Node<N>> and Node<N>'s serde impl is now stack-safe.

      fn test_serde_deep_tree() {
          // Build a right-spine Function chain of depth 64 using TestNode::Add (arity 2).
          // Root = Add(Add(Add(...terminal...), terminal), terminal) — right spine.
          // Use a loop to build from inside out: start with Terminal, wrap in Function Add depth times.
          let mut root: Node<TestNode> = Node::Terminal(TestNode::X);
          for _ in 0..63 {
