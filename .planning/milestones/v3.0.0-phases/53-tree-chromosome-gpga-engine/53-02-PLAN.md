    pub(crate) fn check_limits<N: GpNode>(node: &Node<N>, max_depth: usize, max_node_count: usize) -> Result<(), GaError>:
      if node.depth() > max_depth return Err(GaError::TreeDepthExceeded(format!("depth {} exceeds max_depth {}", node.depth(), max_depth)));
      if node.node_count() > max_node_count return Err(GaError::TreeSizeExceeded(format!("{} nodes exceeds max_node_count {}", node.node_count(), max_node_count)));
      Ok(()).

    pub(crate) fn grow_tree<N: GpNode>(max_depth: usize, rng: &mut impl Rng) -> Node<N>:
      if max_depth <= 1: return Node::Terminal(N::sample_random_terminal(rng)).
      let functions = N::all_functions(); if functions is empty, return Terminal.
      let p_terminal: f64 = 0.5;
      if rng.random::<f64>() < p_terminal: return Terminal(N::sample_random_terminal(rng)).
      pick random function f from functions. children recursive with max_depth - 1.
      Node::Function { value: f, children }.

    Both crossover.rs and mutation.rs import these with use super::node::{check_limits, grow_tree};. No duplication.

    Create src/engines/gp/crossover.rs.

    Define pub enum GpCrossover with one variant: SubtreeCrossover.

    GP operators are dispatched directly by GpGa (single consumer) and never through the global Selection/Crossover/Mutation factory dispatch chain. A factory function would be dead code. Using direct impl methods is intentional for the GP-only subsystem.

    Define the subtree traversal and swap mechanism using an index-path approach. Implement fn replace_subtree_at_index<N: GpNode>(root: &mut Box<Node<N>>, index: usize, replacement: Box<Node<N>>) -> Box<Node<N>> that traverses to the pre-order index and swaps, returning the old subtree. Index 0 replaces the root.

    Implement fn subtree_crossover<N: GpNode + Clone>(p1: &GpChromosome<N>, p2: &GpChromosome<N>, max_depth: usize, max_node_count: usize, rng: &mut impl Rng) -> Result<(GpChromosome<N>, GpChromosome<N>), GaError>:
    1. Count nodes in p1.root and p2.root.
    2. Pick random crossover index i1 in [0, p1.root.node_count()) and i2 in [0, p2.root.node_count()).
    3. Clone both roots to produce child1_root and child2_root.
    4. Extract subtree at i2 from a clone of p2.root → sub2. Extract subtree at i1 from a clone of p1.root → sub1.
    5. Replace subtree at i1 in child1_root with sub2. Replace subtree at i2 in child2_root with sub1.
    6. check_limits(&child1_root, max_depth, max_node_count)?; check_limits(&child2_root, max_depth, max_node_count)?;
    7. Return Ok((GpChromosome::with_root(Box::new(child1_root)), GpChromosome::with_root(Box::new(child2_root)))).

    Add impl GpCrossover: pub fn apply<N: GpNode + Clone>(&self, p1: &GpChromosome<N>, p2: &GpChromosome<N>, max_depth: usize, max_node_count: usize, rng: &mut impl Rng) -> Result<(GpChromosome<N>, GpChromosome<N>), GaError> { match self { GpCrossover::SubtreeCrossover => subtree_crossover(p1, p2, max_depth, max_node_count, rng) } }.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GpCrossover operator → Node tree | Operator clones subtrees from user-provided chromosomes; user cannot inject arbitrary memory access |
| PointMutation → N::all_functions() | User-provided all_functions() may return empty vec or wrong arities — engine handles gracefully (skip) |
| grow_tree depth parameter | If called with max_depth=0, must return Terminal (not recurse infinitely) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-04 | Denial of Service | grow_tree(depth=0) | mitigate | grow_tree with depth <= 1 returns Terminal immediately; no recursion |
| T-53-05 | Denial of Service | N::all_functions() returns very large Vec | accept | PointMutation filters and picks one; O(n) allocation is bounded by user's primitive set size |
| T-53-06 | Tampering | HoistMutation with adversarial tree structure | accept | HoistMutation only shrinks trees — cannot increase node_count; no injection vector |
| T-53-SC | Tampering | npm/pip/cargo installs | accept | No new dependencies introduced in Wave 1 |
</threat_model>
