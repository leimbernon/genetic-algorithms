<objective>
Move construction-time validation for `CellularEngine` and `AlpsEngine` into
`new() -> Result<Self, GaError>` returning `GaError::ConfigurationError` for zero-size
grids/layers (D-06, D-07); change `SelectionOperator::select()` to return
`Result<Vec<Vec<usize>>, GaError>` so the Lexicase/EpsilonLexicase wrong-factory panic becomes
`GaError::SelectionError` (D-09); and convert the order-crossover non-unique-gene-ID panic to
`GaError::CrossoverError`.

Purpose: All three are user-input-reachable: a user picks a zero grid, calls the wrong selection
path with a Lexicase config, or supplies parents with duplicate gene IDs. v3.0.0 permits the
breaking `new()` and trait signature changes.

Output: Result-returning constructors for Cellular/ALPS, a Result-returning SelectionOperator
trait with its cellular cascade handled, and Result-returning OX crossover helpers.

ROADMAP/CONTEXT terminology note (SC-4 vs D-06): ROADMAP SC-4 phrases the Cellular/ALPS change
as moving validation into `build()`, but CONTEXT.md D-06 (locked) specifies `new()`. Confirmed via
grep that BOTH `CellularEngine` and `AlpsEngine` expose a `new(...) -> Self` constructor (cellular
engine.rs:104/108, alps engine.rs:107/111) and have NO `build()` method — there is no builder
pattern on these engines. `new()` per D-06 is therefore the correct and only API entry point;
ROADMAP "build()" is loose terminology, not a different method. Record this discrepancy in the
78-03-SUMMARY.md. Do NOT target a `build()` method (it does not exist).
</objective>
