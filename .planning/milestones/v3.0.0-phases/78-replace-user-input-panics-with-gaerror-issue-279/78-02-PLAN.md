<objective>
Convert EDA, PSO, and CMA engine empty-population `panic!` calls to recoverable
`Err(GaError::InitializationError)` by changing each engine's `run()` return type to a
`Result`-returning form, and convert their fitness-cache `lock().expect(...)` calls to
`Err(GaError::InternalError)` (D-05). v3.0.0 permits the breaking `run()` signature change.

Purpose: A user `init_fn` that returns an empty population is recoverable user input — it must
return an error, not crash. CMA has three independent init sites and EDA has two run() methods;
all must be covered (Pitfalls 2 and 3 in RESEARCH.md).
Output: EDA/PSO/CMA `run()` returning `Result<...Result<U>, GaError>`; all empty-pop panics and
cache-lock expects in these three files converted.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user init_fn → engine run() | A user-supplied `init_fn` that returns an empty population is untrusted input crossing into the engine; previously aborted via panic |
| panicking worker thread → fitness-cache Mutex | Cache mutex poison in eda/pso/cma run loops |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-78-03 | Denial of Service | eda/pso/cma run() empty-population paths | mitigate | Return `Err(GaError::InitializationError)` instead of `panic!`, surfacing the bad init_fn to the caller as a recoverable error |
| T-78-04 | Denial of Service | eda/pso/cma fitness-cache mutexes | mitigate | Convert `lock().expect()` to `map_err(GaError::InternalError)?` so cache poison does not abort the process |
| T-78-05 | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — pure source edits |
</threat_model>
