<objective>
Add the `GaError::InternalError(String)` variant (D-04, D-10) and convert every mutex
`.unwrap()` / `.expect("...poisoned")` call in the core GA generation loop and fitness-cache
helpers to recoverable `Err(GaError::InternalError(...))` returns (D-03, D-05).

This is the foundation plan: the `InternalError` variant it adds is required by Plans 02 and 03.

Purpose: Mutex poisoning (caused by a panicking thread) must surface as a recoverable error,
never crash the process. A dedicated variant keeps it distinct from user config/mutation errors.
Output: New error variant + converted AOS and fitness-cache mutex call sites in `ga/`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| panicking worker thread → shared Mutex | A thread that panics while holding a fitness-cache or AOS-state lock poisons the mutex; the next `lock()` would otherwise panic and crash the whole run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-78-01 | Denial of Service | generation.rs / ga cache mutexes | mitigate | Convert `.unwrap()`/`.expect()` on `lock()` to `map_err(GaError::InternalError)?` so poison surfaces as a recoverable error instead of a process abort |
| T-78-02 | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — pure source edits, no new dependencies |
</threat_model>
