    Step B — Write `.github/workflows/examples-smoke.yml` following the template in 47-PATTERNS.md § examples-smoke.yml section. Specifically:

    ```
    name: Examples Smoke Test

    on:
      push:
        branches: [main, "milestone/**", "feat/**", "fix/**"]
      pull_request:
        branches: [main, "milestone/**"]

    jobs:
      examples-smoke:
        runs-on: ubuntu-latest
        strategy:
          fail-fast: false
          matrix:
            example:
              - knapsack_binary
              - onemax_binary
              - onemax_extension
              - rastrigin
              - nsga2_zdt1
              - island_model
              - job_scheduling
              - niching
              - hall_of_fame_demo
              - aos_demo
        steps:
          - uses: actions/checkout@v4
          - name: Install stable toolchain
            uses: dtolnay/rust-toolchain@stable
          - name: Cache cargo registry and target
            uses: Swatinem/rust-cache@v2
            with:
              key: "examples-smoke-${{ matrix.example }}"
          - name: Run example (smoke)
            run: cargo run --example ${{ matrix.example }} --release
            timeout-minutes: 5
    ```

    Adjust as follows:
    - If any example requires features, branch on the matrix entry to inject `--features` or use a per-example `features:` matrix key with `include:`. Example: if `nsga2_zdt1` requires `--features benchmarks`, add a parallel include block per actions matrix syntax.
    - Add `timeout-minutes: 5` per matrix job to prevent a runaway example from hanging the CI for 6 hours.
    - Ensure `fail-fast: false` so that one example's failure does not cancel the rest — diagnosing all failures at once is faster than serializing.
