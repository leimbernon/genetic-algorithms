### Integration Gaps (tech debt — non-blocking)

**ISSUE-1 — Reporter not used in any example (REP-01, REP-03, REP-04)**

`with_reporter()` exists at `ga.rs:523` and all 4 hooks fire correctly. However, all 6 new examples use raw `run_with_callback` closures and never call `with_reporter()`. `SimpleReporter` and `DurationReporter` have no runnable E2E demonstration path.

**ISSUE-2 — Visualization not called in any example (VIZ-01, VIZ-02, VIZ-03)**

`plot_fitness`, `plot_diversity`, `plot_histogram` are implemented and unit-tested. `Ga::stats()` is public. No example collects stats and calls any plot function. The E2E flow from `ga.run()` → `ga.stats()` → `plot_fitness(..., "output.png")` has no runnable demonstration.

**ISSUE-3 — ListChromosome unused in examples (LIST-01, LIST-02, LIST-04)**

`ListChromosome<T>` and `list_random_initialization*` are fully implemented and exported. `job_scheduling.rs` (the most natural fit) uses `RangeChromosome<i32>` with `Some(false)` uniqueness instead. No example calls `list_random_initialization`.

### Examples Layer (Medium — affects discoverability)

Three Phase 7–9 features are implemented and tested but have no runnable E2E demonstration:

1. **Reporter** — Add `.with_reporter(Box::new(SimpleReporter::new(50)))` to `rastrigin.rs`
2. **Visualization** — Add `#[cfg(feature = "visualization")]` block to `rastrigin.rs` calling `plot_fitness` and `plot_diversity`
3. **List** — Update `job_scheduling.rs` to use `ListChromosome<char>` for job labels, or add a new `list_alphabet.rs` example

These are low-risk additions that would significantly improve feature discoverability without changing the library API.
