Create 6 new markdown files in docs/ for the multi-objective engines and shared module. Each follows the D-04 ficha tecnica template adapted for markdown.

**docs/nsga3.md:** NSGA-III per-engine guide.
- Description: Many-objective NSGA-III with reference-point based niching. Auto-generates reference points via Das-Dennis simplex lattice. Survivors selected by associating each solution with the closest reference line then performing niche preservation.
- When to Use: 3+ objectives, continuous variables, problems where crowding distance breaks down
- Mandatory params: population_size, max_generations, dimensions, n_objectives, fitness_fn (returning Vec<f64>)
- Optional params: divisions (number of divisions per objective for reference point generation), reference_points (user-supplied)
- Complete example: Nsga3Ga on DTLZ2 with 3 objectives
- Cross-reference: When to Choose NSGA-III vs MOEA/D
- References: Deb & Jain (2014)

**docs/moead.md:** MOEA/D per-engine guide.
- Description: Decomposition-based MOEA. Decomposes MOP into N scalar sub-problems using weight vectors. Each sub-problem has a neighborhood. Offspring compete only within neighborhood. Ideal point tracks best per-objective values.
- When to Use: 2+ objectives, continuous, well-structured Pareto fronts
- Mandatory params: population_size, max_generations, dimensions, n_objectives
- Optional params: scalarization (Tchebycheff default, PBI with θ), neighborhood_size
- Complete example: MoeaDGa on DTLZ2 with Tchebycheff
- Cross-reference: When to choose MOEA/D vs NSGA-III
- References: Zhang & Li (2007)

**docs/spea2.md:** SPEA2 per-engine guide.
- Description: Archive-based Strength Pareto EA. Fitness = raw strength (domination count) + density (k-NN distance). Archive managed via environmental selection + Euclidean truncation.
- When to Use: 2+ objectives, fine-grained Pareto front approximation
- Mandatory params: population_size, archive_size, max_generations
- Optional params: k (density parameter)
- Complete example: Spea2Ga on ZDT1
- Cross-reference: When to choose SPEA2 vs NSGA-II
- References: Zitzler, Laumanns, & Thiele (2001)

**docs/sms_emoa.md:** SMS-EMOA per-engine guide.
- Description: Steady-state (mu+1) hypervolume-based MOEA. Each generation removes the individual with smallest hypervolume contribution. Hypervolume simultaneously captures convergence and diversity.
- When to Use: 2+ objectives (best at 2-3), single metric quality evaluation
- Mandatory params: population_size, max_generations, dimensions, n_objectives
- Optional params: reference_point (for hypervolume computation)
- Complete example: SmsEmoaGa on ZDT1
- Cross-reference: When to choose SMS-EMOA vs IBEA vs NSGA-II
- References: Beume, Naujoks, & Emmerich (2007)

**docs/ibea.md:** IBEA per-engine guide.
- Description: Indicator-Based EA using I_eps+ indicator. Pairwise fitness: -e^(-I(b,a)/(c*kappa)). Environmental selection removes lowest-contributing individual.
- When to Use: 2+ objectives, indicator-based selection without hypervolume
- Mandatory params: population_size, max_generations, dimensions, n_objectives
- Optional params: kappa (scaling factor, default 0.05)
- Complete example: IbeaGa on ZDT1
- Cross-reference: When to choose IBEA vs SMS-EMOA
- References: Zitzler & Kunzli (2004)

**docs/multi_objective.md:** Shared multi-objective module guide.
- Overview: Shared utilities for all MO engines — Pareto dominance, non-dominated sorting, crowding distance, reference point generation, quality indicators
- Key types: ParetoDominance, NonDominatedSort, CrowdingDistance, ReferencePoints
- Quality indicators sub-section: Hypervolume (2D Lebesgue), GD, IGD, Spread
- Usage example: Computing quality indicators on a Pareto front
- See Also: links to nsga2, nsga3, moead, spea2, sms_emoa, ibea guides

- Usage example: Configuring AOS with multiple operators

- Configuration: builder method, radius selection guidance
- Usage example: GA with niching on a multimodal problem

**docs/extension.md:** Extension strategies guide.

- Key concepts: ExtensionConfiguration, diversity threshold, extension_trigger, extension operators
- Configuration: builder method, threshold, strategy selection
- Usage example: GA with MassExtinction extension
- See Also: onemax_extension example

- Key concepts: GaError variants (InvalidConfiguration, PopulationExhausted, etc.), Result<T, GaError> return type
- Error table: every variant with description and mitigation
- Usage example: Handling errors in GA construction and execution

**docs/initializers.md:** Population initialization guide.

- Key concepts: InitializationFn type, generic_random_initialization, range_random_initialization, seeded initialization, checkpoint initialization
- Usage example: Random init, seeded init, checkpoint resume
