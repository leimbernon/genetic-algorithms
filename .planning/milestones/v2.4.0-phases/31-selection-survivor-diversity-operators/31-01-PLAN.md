Purpose: Closes requirement SEL-01. Gives users a low-cost diversity mechanism that composes with all existing crossover and mutation operators without engine wiring.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied `niche_radius` → `clearing()` | Configuration value can be any f64 (NaN, negative, infinity) |
| User-supplied fitness function → `chromosome.fitness()` | Fitness can be NaN/infinity, breaking ordering and arithmetic |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Tampering (logical) | `clearing(niche_radius)` | mitigate | At entry: `if !niche_radius.is_finite() \|\| niche_radius < 0.0 { return vec![]; }` (Task 1 step 6). Prevents nonsensical niche definitions and NaN-poisoned comparisons. |
| T-31-02 | Tampering (logical) | distance comparison `(fa - fb).abs() < niche_radius` | mitigate | NaN fitness values never satisfy `<`, so they are treated as never matching (no panic, no spurious clearing). Documented in Task 1 step 6. |
| T-31-03 | Denial of Service (panic) | sorted-by-fitness niche identification | mitigate | Use `partial_cmp(...).unwrap_or(Ordering::Equal)` for fitness sort (mirrors fitness.rs line 188 pattern). Prevents panic on NaN. |
| T-31-04 | Information Disclosure | log statements at debug/trace | accept | Library logs only indices and counts, no chromosome data. Existing operators follow same pattern. No PII. |
| T-31-05 | Elevation of Privilege | unsafe code | accept | No `unsafe` introduced. Pure-safe Rust. |
